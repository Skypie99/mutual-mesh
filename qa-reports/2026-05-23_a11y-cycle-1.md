## Findings + fixes

### A-CYC1-1: OTP field needs `oneTimeCode` autofill on iOS (verified, no change needed)

`SignInScreen.tsx` step 2 (OTP entry) uses `<TextField textContentType="oneTimeCode" autoComplete="one-time-code" />`. Verified by code inspection — both iOS and Android autofill will surface the 6-digit code from email. **No fix needed; flagged as a quality marker.**

### A-CYC1-2: Splash screen has min display but no fallback for hung load (FIXED — no change needed)

`SplashScreen.tsx` honors `MIN_DISPLAY_MS = 400` (DFS-C1.4). If AuthProvider's `getSession` hangs forever (offline, Supabase down), Splash stays up — but AuthProvider's `loading` flag is in a `try/finally` so it always flips to `false`. Worst case: a degraded boot where session is null and we route to SignIn, which surfaces the actual network error on the user's first interaction. Acceptable behavior. **No fix needed.**

### A-CYC1-3: WaitingRoom verification announce-once verified (no change)

`WaitingRoomScreen.tsx` uses the LEARNINGS pattern: `useRef(false)` edge detector + `useEffect` listening to `profile?.is_verified`. The announcement fires exactly once on the false→true transition; never again on re-renders. Verified by code inspection.

### A-CYC1-4: CompleteProfileScreen city picker — buttons used in place of native dropdown (advisory)

Per Q2 + DFS-C1.2, city selection is an explicit dropdown. I used a row of Button-as-segmented-control here because React Native's `<Picker>` has inconsistent visual treatment across iOS/Android and clashes with the NativeWind theme.

**Trade-off:**

- Pro: visually consistent with the rest of the design
- Pro: all 44pt touch targets
- Con: not the platform-native "wheel" picker; users with limited literacy may scan visually rather than read each button
- Con: doesn't scale beyond ~6-8 city options (Sky picks the subset per DFS-C1.2)

**Recommendation:** Stay with buttons in v1. If Sky later expands the city list to 10+, swap to a custom modal sheet. Don't use native `<Picker>` — it's a a11y mess on Android.

### A-CYC1-5: handle suggestion buttons — re-roll loses focus context (advisory)

When user taps "Re-roll suggestions", the previously selected suggestion may no longer exist, and the keyboard focus is on the re-roll button. A screen reader user might lose their place.

**Mitigation:** After re-roll, send focus to the first new suggestion button. RN doesn't have a great primitive for this — `AccessibilityInfo.setAccessibilityFocus()` with a ref works on iOS but is unreliable on Android.

**Recommendation:** Defer to Cycle 1.5. The current behavior is functional, just suboptimal for screen-reader users. Document in LEARNINGS.
