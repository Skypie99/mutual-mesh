## BLOCKER — Fixed inline on this branch

### BLOCKER-1: Missing `<html lang>` attribute

**WCAG criterion:** 3.1.1 Language of Page (Level A)
**File:** `app.json`
**Before:** `"web": { "bundler": "metro" }`
**After:** `"web": { "bundler": "metro", "lang": "en", "title": "Mutual Mesh" }`

**Why it matters:** Screen readers use the `lang` attribute to select the correct speech synthesizer language and pronunciation rules. Without it, a VoiceOver or NVDA user whose default language is not English will hear garbled pronunciation. This is a Level A failure — the lowest possible bar and a blocking criterion.

**Fix applied:** Added `"lang": "en"` to the `web` block in `app.json`. Expo web's Metro bundler injects this as `<html lang="en">` on the generated HTML shell.

---

### BLOCKER-2: Missing `<title>` element

**WCAG criterion:** 2.4.2 Page Titled (Level A)
**File:** `app.json`
**Before:** No `title` key in `web` block
**After:** `"title": "Mutual Mesh"` added alongside `lang`

**Why it matters:** Every web page must have a descriptive `<title>`. Without one, the browser tab shows the raw filename or URL and screen readers cannot announce the page name when the document loads. Level A failure.

**Fix applied:** Added `"title": "Mutual Mesh"` to the `web` block in `app.json`. This becomes `<title>Mutual Mesh</title>` in the generated HTML shell.

### BLOCKER-3: Leaflet keyboard trap

**WCAG criterion:** 2.1.2 No Keyboard Trap (Level A)
**File:** `src/components/PlatformMapView.web.tsx`

**What was happening:** Leaflet's built-in keyboard handler (enabled by default) captures `ArrowUp / ArrowDown / ArrowLeft / ArrowRight` and `+/-` keys once any element inside the `MapContainer` tile pane receives focus. A keyboard-only user tabbing into the map area had no standard way to escape — Tab continued cycling through Leaflet's internal DOM nodes (tile pane, attribution link, zoom controls) without returning to the page flow. This is a Level A failure under WCAG 2.1.2.

**Fixes applied (two-part):**

1. **`keyboard={false}` on `<MapContainer>`** — disables Leaflet's keyboard handler entirely. Leaflet's built-in zoom controls (`+`/`−`) are rendered as `<a>` elements in the control layer, which is outside the tile pane; they remain Tab-reachable before and after the map region without the keyboard handler.

2. **Visually-hidden `<p>` inside the wrapper `<div>`** — informs screen reader and keyboard users that the map is not fully keyboard-navigable and directs them to the FSA filter chips (the equivalent data surface). Copy: *"This map is not fully keyboard accessible. Use the FSA filter chips above to navigate resources by area."* Styled with the standard screen-reader-only clip pattern (no Tailwind class added to avoid web-specific class bleed into the native bundle).

**Why not a skip-link?** A skip-link would require a visible focusable target to appear on focus, which is a more invasive change and requires coordination with the navigation shell. The `keyboard={false}` fix removes the trap; the sr-only notice provides the advisory context. A full skip-link is recommended as a future enhancement (see ADVISORY-3 below).

## ADVISORY — Documented, not fixed (best practice / not a hard WCAG AA fail)

### ADVISORY-1: Leaflet zoom controls lack visible focus indicators in some browser/theme combos

**WCAG criterion:** 2.4.7 Focus Visible (Level AA) — conditional
**File:** `src/components/PlatformMapView.web.tsx`

Leaflet renders its zoom controls as `<a>` elements with its own CSS. In high-contrast mode on Windows, the default Leaflet focus outline may be suppressed. This is browser/OS-dependent and not a reliable WCAG fail in standard Chrome/Safari, but worth noting.

**Recommendation:** In a future Leaflet styling pass, add a CSS rule targeting `.leaflet-control a:focus-visible { outline: 2px solid <accent-token>; outline-offset: 2px; }` inside the `leaflet.css` import override. Use `colors.light.accent` (`#1F7A6A`) as the outline color. Do not add raw hex — proposal should go through Dani for token approval first.

### ADVISORY-2: `ResourceMapScreen` — `accessibilityRole="summary"` on hidden list may be misread

**WCAG criterion:** 4.1.2 Name, Role, Value (Level AA) — advisory
**File:** `src/screens/ResourceMapScreen.tsx` (lines 319–325 and 430–436)

The hidden list `<View>` uses `accessibilityRole="summary"`. On web, React Native Web maps `accessibilityRole` to ARIA `role`. `"summary"` maps to `role="note"` in React Native Web's role map (not a standard `<summary>` element). While this is functional, `role="note"` is a landmark role that may create an unexpected landmark in screen reader navigation (e.g., NVDA's landmark list). The intent is a supplementary description, not a landmark.

**Recommendation:** Change `accessibilityRole="summary"` to `accessibilityRole="none"` (or remove it) on the zero-height hidden list `<View>` and keep only the `accessibilityLabel`. The label text already carries the full FSA summary. This removes the spurious landmark without losing any information.

**Scope:** Two instances — lines 319–325 (fallback path) and 430–436 (map-installed path). This is a Shamus fix (touches `src/screens/`); Alex documents it here.

---

### ADVISORY-3: No skip-link for keyboard users to bypass the map region

**WCAG criterion:** 2.4.1 Bypass Blocks (Level A) — advisory in this context
**File:** `src/components/PlatformMapView.web.tsx`

WCAG 2.4.1 requires a mechanism to skip repeated blocks of content. On web, the map region is a large visual block that keyboard users must tab through (zoom controls + attribution link). The `keyboard={false}` fix (BLOCKER-3) prevents the trap, but keyboard users still must Tab through two or three Leaflet control elements to exit the map region.

**Recommendation:** In a future a11y pass, add a visually-hidden skip link immediately before the `<MapContainer>` that jumps to the FSA chip list: `<a href="#fsa-chip-list" className="sr-only focus:not-sr-only">Skip map to neighborhood list</a>`. The FSA chip `<ScrollView>` would need an `id="fsa-chip-list"` (or `nativeID` for RN web). This is a Level A best practice; the current state (few focusable elements, sr-only notice present) is acceptable for MVP.
