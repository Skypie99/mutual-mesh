## Findings + fixes

### A1: Pressable `Card` missed 44pt minimum hit-target (FIXED)

**Issue:** `Card` becomes pressable when `onPress` is set, but had no `minHeight`. A card with very short content (e.g., a one-line caption) could fall below the 44pt minimum required by WCAG 2.5.5.

**Fix:** Added `style={{ minHeight: TOUCH_TARGET_MIN }}` to the Pressable branch. Non-pressable cards keep no minimum (they're not targets).

### A2: `TextField` hardcoded placeholder color + multiline alignment (FIXED)

**Issue (a):** `placeholderTextColor="#6B5640"` was a hex literal — violates the "no raw hex" rule in CLAUDE.md gotcha #2.

**Fix:** Use `colors.light.textMuted` / `colors.dark.textMuted` via `useColorScheme()`. The placeholder now picks the correct mode token.

**Issue (b):** Multiline TextInputs default `textAlignVertical='center'` on Android, putting the caret in the middle of the field. Confusing for users typing a multi-line description.

**Fix:** When `multiline={true}`, set `textAlignVertical='top'`.

## Advisory items (for Shamus during Phase 0b)

### B1: Photo loading states

`ResourceDetailScreen` renders an `<Image>` directly from `resource.photo_url`. When the URL is loading, broken, or signed-URL-expired, a screen reader currently announces "Photo of {name}" but the image is empty. Add a `defaultSource` + an `onError` handler that falls back to a captioned empty state. Estimated time: 30 min.

### B2: AccessibilityInfo announce on FlashBanner

The `FlashBanner` primitive doesn't exist yet (specced in DESIGN.md but not built in Loop 7 — defer to Cycle 1). When built, follow the AccessMap pattern: `useRef` + `useEffect` edge-detector so the announcement fires exactly once on transition, not every render (LEARNINGS.md will record the recipe).

### B3: ScreenReader-only "Reserved" state on `StatusPill`

`StatusPill` shows "Available" or "Reserved" visually. Screen readers get `accessibilityLabel="Status: Available"`. Consider adding `accessibilityValue` instead so the status is announced as a state, not a label. Minor — current works.

### B4: Form field order / `tabIndex`

On native, focus order follows tree order — currently correct. On web bundle, verify `tabIndex` matches visual order especially in `AddResourceScreen` (description is multiline; tab might jump unexpectedly). Re-test in Cycle 7 web audit.

### B5: Dynamic Type at 200% scale

Per DESIGN.md, layouts must accommodate up to 200% font scale. The current stubs use `flex-1` and `numberOfLines` to prevent overflow, but I have not visually tested at max scale. Worth a one-off check in iOS Simulator with "Larger Text" set to max. Defer to Shamus.
